# ตรวจสอบภาพรวมเทียบข้อกำหนด Excel

วันที่ตรวจ: 15 กันยายน 2026

## ข้อสรุป

ระบบปัจจุบันเป็นเว็บแสดงข้อมูลอันดับและสถิติที่ใช้งานได้บางส่วน แต่ยังไม่เป็นระบบบริหารจัดการตาม Excel ทั้ง 7 ส่วน การเพิ่มหน้า /admin สำหรับแก้ช่องอย่างเดียวจะยังไม่ครอบคลุมไฟล์นี้

แหล่งข้อกำหนด: `VTuberThai_Ranking_Template.xlsx` ในรากโปรเจกต์ มี 7 ชีต รวม 64 ฟิลด์หัวตาราง และแถวตัวอย่าง ไม่พบสูตร คอมเมนต์ หรือ data validation ในทุกชีต จึงใช้เป็นโครงสร้างข้อมูลได้ แต่ยังไม่ใช่ข้อกำหนดกระบวนการทำงานที่สมบูรณ์

ขอบเขตตรวจ: อ่าน workbook ทุกชีต, โค้ด frontend และ Functions, schema และจำนวนแถวใน D1 จริง, API ออนไลน์บางรายการ และ production build ไม่แก้โค้ดแอป ไม่เขียนฐานข้อมูล ไม่ deploy ในการตรวจครั้งนี้ การตรวจ schema ใช้คำสั่งอ่านอย่างเดียวและรายงาน rows_written=0

## สภาพระบบจริง

- Frontend: React + Vite + Tailwind; มีอันดับ ค้นหา โปรไฟล์ และเปรียบเทียบ พร้อม Light/Dark/System
- Backend ที่ใช้งาน: Cloudflare Pages Functions + Hono + D1
- D1 มีตาราง vtubers, stats_snapshots, rankings เท่านั้น (ไม่นับตารางภายในระบบ)
- ข้อมูลจริงขณะตรวจ: VTuber 3 ช่อง (VTuber A/B/C), snapshots 6 แถว, rankings 9 แถว เป็นชุดข้อมูลตัวอย่าง
- อันดับมี monthly followers/views เดือน 2026-09 และ alltime followers; ยังไม่มี alltime views
- ยังไม่มี route หน้า /admin, login, session หรือ middleware ตรวจสิทธิ์ผู้ดูแล
- README และเอกสารบางส่วนยังอธิบาย Django/Celery/PostgreSQL ที่ไม่ใช่ระบบ deploy ปัจจุบัน ไฟล์ backend เดิมอยู่ในสถานะลบค้างใน Git
- ไม่พบตัวดึงข้อมูล YouTube, scheduled handler, ตัวคำนวณอันดับ, D1 migration SQL หรือ automated tests ใน source ปัจจุบัน; ไม่ได้ตรวจระบบภายนอกทุกตัว จึงไม่สรุปว่าไม่มี automation นอกโปรเจกต์

## ข้อบกพร่องและความเสี่ยงที่ตรวจพบ

### 1. API แอดมินยังเปิดอ่านโดยไม่ยืนยันตัวตน — ควรแก้ก่อนเพิ่มการเขียนข้อมูล

`frontend/functions/api/[[path]].js:278` ส่ง SELECT * FROM vtubers โดยไม่มี auth middleware การเรียก GET `/api/v1/admin/vtubers/` โดยไม่ส่งข้อมูลล็อกอินคืน HTTP 200 ขณะตรวจ ปัจจุบันเป็น endpoint อ่านอย่างเดียว ยังไม่มีหลักฐานว่าสามารถแก้ไขหรือลบผ่าน endpoint นี้ได้ แต่จะเปิดเห็นทุกแถวรวมช่องที่ปิดสถานะ จึงควรบังคับตรวจสิทธิ์ก่อนเพิ่ม CRUD

### 2. หมวดอันดับคนละความหมาย — ต้องปรับโมเดลก่อนทำแอดมิน

Excel Categories!A2:D3 กำหนด Overall Ranking และ Popularity ผ่าน category_id แต่ DB rankings.category จำกัดเฉพาะ followers/views ส่วน vtubers.category คือแนวเนื้อหา gaming/singing ฯลฯ ทั้งสามแนวคิดไม่ใช่สิ่งเดียวกัน ต้องแยก “ประเภทเนื้อหา”, “หมวดอันดับ” และ “ตัวชี้วัด” ไม่ควรแทนที่กันโดยตรง

### 3. ยอดผู้ติดตามรวมคำนวณผิด

`frontend/functions/api/[[path]].js:240` ใช้ MAX(followers) ของ snapshots ทั้งหมด แต่ชื่อผลลัพธ์ total_followers_all สื่อว่าเป็นผลรวม API ปัจจุบันคืน 1,250,000 ขณะที่ SUM ของ snapshot ล่าสุดต่อช่อง active ใน D1 ได้ 2,980,000 หากความหมายคือยอดรวมทุกช่องต้องแก้สูตร ตัวเลขนี้ยังไม่ได้แสดงในหน้า Home ปัจจุบัน แต่มีผลกับ API และรายงานในอนาคต

### 4. ปิดสถานะช่องแล้วรายการอันดับอาจยังแสดง

`frontend/functions/api/[[path]].js:43` กรอง rankings ตาม period/category/month แต่ query ที่ JOIN vtubers ไม่กรอง v.is_active ในขณะที่ค้นหา/โปรไฟล์กรอง active แล้ว จึงต้องแก้พร้อมฟังก์ชันเปิด/ปิดช่อง รวมถึงกำหนดนโยบายอันดับย้อนหลังว่าจะเก็บแสดงหรือซ่อน ไม่ได้ทดสอบปิดช่องในฐานข้อมูล production

### 5. current_rank และ top_gainer ไม่เลือกเดือนล่าสุดอย่างชัดเจน

`frontend/functions/api/[[path]].js:134-140` อ่านอันดับทุกเดือนแล้วเขียนทับ key เดียวโดยไม่จัดลำดับเดือน จึงอาจได้อันดับเก่าเมื่อมีหลายเดือน ส่วน top_gainer ที่บรรทัด 248 กรองแค่ monthly ไม่กรองเดือน/หมวด เห็นความเสี่ยงจากโค้ด ยังไม่พิสูจน์ผลผิดในชุดข้อมูลที่มีเพียงเดือนเดียว

### 6. การเลือกเดือนและการแบ่งหน้ายังไม่ครบ

`frontend/src/pages/HomePage.jsx:21` ขอ 50 รายการคงที่ ไม่มีตัวเลือกเดือนและปุ่มเปลี่ยนหน้า API รองรับ month/offset แต่ next/previous ไม่พก month และ limit เดิม ทำให้การไล่อันดับย้อนหลังหลายหน้าอาจเปลี่ยนชุดข้อมูล

### 7. โครงสร้างอันดับ All Time ยังกันข้อมูลซ้ำไม่ครบ

D1 schema ใช้ UNIQUE(period, category, month, vtuber_id) แต่ All Time ใช้ month=NULL ซึ่ง SQLite ยอมให้มีหลายแถวที่ค่า NULL ภายใต้ unique constraint ได้ ต้องกำหนด unique index สำหรับ All Time แยก หรือใช้ key ที่ไม่เป็น NULL ก่อนเพิ่มการคำนวณซ้ำ ประเด็นนี้เป็นความเสี่ยงของ schema ไม่ได้พบแถวซ้ำในการตรวจครั้งนี้

### 8. ขาดกระบวนการสร้างข้อมูลและทดสอบระบบ

Functions อ่านผลอันดับที่มีแล้ว; POST compare เป็นการอ่านสถิติมาเทียบ ไม่ใช่ CRUD ไม่พบการ import Excel, sync YouTube, คำนวณรอบใหม่ หรือ tests ในโค้ดที่ยังอยู่ ข้อมูลใหม่ที่เพิ่มเข้ารายชื่อจึงไม่ได้มีหลักฐานว่าจะขึ้นอันดับอัตโนมัติ

## สิ่งที่ Excel ยังไม่ระบุ — ต้องแยกจาก requirement ที่ยืนยันแล้ว

1. สูตร Overall Ranking และ Popularity: ตัวอย่าง Ranking!E2:I2 มีผู้ติดตาม 100000, วิว 1000000, วิดีโอ 200, score 1000, rank 1 แต่ไม่มีสูตร ไม่สามารถอนุมานน้ำหนักคะแนนได้
2. สิทธิ์ manager/staff: พบชื่อบทบาท แต่ยังไม่มีตารางสิทธิ์ เช่น ใครเพิ่มช่องได้ ใครเผยแพร่อันดับได้ ใครจัดการผู้ใช้ได้
3. วิธีล็อกอิน: มี username/password_hash/email ใน schema แต่ไม่ยืนยันว่าต้องใช้รหัสผ่านในเว็บเท่านั้น Cloudflare Access ยังเป็นทางเลือกได้โดยมี users/roles ภายในประกอบ; ผู้ใช้ยังไม่ได้เลือกระบบยืนยันตัวตนจากคำถามก่อนหน้า
4. สถานะของแต่ละรายการ: พบ active เป็นตัวอย่าง แต่ไม่ระบุ inactive/draft/published หรือกติกาลบ
5. แหล่งสถิติ: กรอกเอง, import Excel หรือดึง YouTube และข้อมูลวิดีโอแบบใด ยังไม่ได้ระบุใน workbook
6. รายงาน: มี metadata ของ ranking_summary แต่ยังไม่กำหนดหน้าตารายงานหรือชนิดไฟล์ PDF/Excel/CSV
7. รอบอันดับ: มี YYYY-MM และ monthly แต่ไม่ระบุวันตัดยอด เขตเวลา การเสมอกัน อันดับใหม่ และการคำนวณซ้ำ
8. Excel เป็น requirement schema ไม่ได้ยืนยันว่าต้องใช้ Excel เป็นฐานข้อมูลหรือมีฟังก์ชัน import/export ทุกชีต

ไฟล์มี password_hash ตัวอย่าง จึงไม่คัดลอกค่าเหล่านั้นลงรายงาน และไม่ถือว่าเป็นบัญชี production ที่ใช้เข้าสู่ระบบได้

## แนวทางดำเนินงานที่เสนอ (ยังไม่ใช่ requirement ที่อนุมัติ)

1. **ฐานข้อมูลและการยืนยันตัวตน:** ออก migration เพิ่ม Users/Categories/Reports/AuditLogs/Settings; เติมฟิลด์ Vtubers/Ranking, รักษา stats_snapshots, กำหนด mapping ID เดิม และเลือกวิธีล็อกอิน/สิทธิ์ manager-staff
2. **แอดมินสำหรับงานประจำ:** login/logout + protected API; รายการ/เพิ่ม/แก้ไข/เปิดปิด VTuber; validation ข้อมูลและ slug; บันทึกผู้แก้ไขผ่าน AuditLogs พร้อมธุรกรรมเดียวกับการเปลี่ยนข้อมูล; UI มินิมอลและสองธีม
3. **หมวดและรอบอันดับ:** CRUD หมวดอันดับ, settings, เลือกรอบ, วิธีรับสถิติ, สูตรที่ยืนยันแล้ว, ตรวจข้อมูลก่อนบันทึกอันดับ, กติกาเผยแพร่และการคำนวณซ้ำ
4. **ผู้ใช้ รายงาน และการตรวจย้อนหลัง:** หน้าจัดการบัญชีสำหรับผู้มีสิทธิ์, รายงานตามรอบ/หมวด, ประวัติการทำงานที่แก้ไขจาก UI ไม่ได้
5. **ทดสอบก่อน deploy:** ผู้ไม่ล็อกอินอ่าน/เขียน admin ไม่ได้; staff ถูกจำกัดตามสิทธิ์; เพิ่ม/แก้ไข/ปิดช่องถูกบันทึกประวัติ; คะแนนตรงตัวอย่างที่ตกลง; รายงานอ้างอิงรอบเดียวกับอันดับ; migration รักษาข้อมูลเดิม
